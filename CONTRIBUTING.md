# Contributing

## Workflow

1. Define the change and acceptance criteria in the private Susu Project Conductor Workbench.
2. Open a dedicated engine branch and worktree from the intended base.
3. Implement the smallest source, test, migration, and documentation change required.
4. Run `npm run check` locally; GitHub Actions runs the same command.
5. Build and verify a candidate package once packaging exists.
6. Test fresh installation in disposable repositories.
7. Test updates while preserving substance and administrator configuration.
8. Record Windows and macOS acceptance evidence for supported clients.
9. Prepare a human-selected release version after acceptance passes.
10. Obtain human approval before merging.
11. Publish the approved engine tag and release through release automation.
12. Let a Shrimp administrator review and adopt the release.
13. Align connected Workbenches through the Oversoul gate-opening handshake.
14. Record the outcome and remaining gaps in Susu Project Conductor.

Steps 5 through 13 describe the approved lifecycle. Their automation remains outside the extraction baseline.
