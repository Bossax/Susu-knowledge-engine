# Changelog

## Unreleased

- Extracted the Workbench connector, shared artifact handlers, Oversoul skill, and tests from Susu Project Conductor with their Git history.
- Replaced copied-layout compatibility paths with one canonical engine layout.
- Replaced component version fields with the engine release from `engine.json`.
- Added `npm run pack`, building a deterministic candidate package identified by commit and sha256 bundle hash. The package carries `engine.json` so it names its own release.
- Added `npm run update`, the administrator-controlled Shrimp update. It verifies the bundle before extracting, writes `.shrimp/system/connector/` and `.shrimp/release.json`, preserves `.shrimp/project.json` and all substance, plans by default, and leaves committing to the administrator.
- Moved the atomic tree replacement and its rollback from the skill installer into `shared/fs.mjs` as `replaceTree`, now shared by the skill installer and the Shrimp updater.
- Added the gate-time engine alignment handshake to `linked-repo.mjs`: opening the gate now reads Shrimp's `.shrimp/release.json`, compares it against the locally-installed Oversoul's `engine.json`, and replaces the local skill in place from `.shrimp/system/connector/oversoul` when Shrimp is ahead. Never downgrades a locally newer installation; a Shrimp without `.shrimp/release.json` is unaffected. This file ships standalone inside the installed skill, so the comparison and swap are self-contained rather than importing `shared/`.
- Split `inspect()`'s single `diagnostics` array into `diagnostics` (hard, gate-closing: engine incompatibility, broken repository identity, an invalid worktree link, or an unverified package) and `drift` (soft, informational: dirty, ahead, behind, divergent, detached HEAD, or a failed fetch). Content drift no longer closes the gate — it may still be read, reviewed, tested, edited, and prepared for a human-approved local commit. `prepare`'s fast-forward still requires both to be clean before it attempts a merge.
- Added a `commit` command: prepares a human-approved local commit of existing dirty content (`git add -A && git commit -m "<message>"`). The explicit, non-empty message argument is the approval signal; refuses without one, no-ops on a clean worktree, and refuses when a hard diagnostic is present. Never merges, rebases, resets, force-pushes, or pushes to a remote.
- Fetch failures are now classified (network, authentication, repository, repository-corruption, unknown) from the real Git stderr/message, which is always preserved verbatim in the reported drift entry, instead of one opaque "fetch failed" string.
- `run`'s rejection of `'actions'`-context capabilities (e.g. a future `publish`) now carries its own dedicated message, marking it as a deliberate placeholder guard rather than an incidental side effect of the interactive-only check.
- `engineAlignment` now also verifies the connector's bundle hash, not just its `engineRelease` string: each successful gate-time align stamps the locally installed `engine.json` with the bundle hash it aligned to, and a later check with a matching `engineRelease` but a different hash is reported as `action:'failed'` (a corrupted or re-published package under the same version), rather than silently passing as `current`. A local install with no recorded hash yet (never aligned through this path) has nothing to compare and is left unverified rather than flagged.
